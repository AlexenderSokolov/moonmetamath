# MoonMetamath 0.1.1 / 0.2 / small AI completion Implementation Plan

> For agentic workers: use Superpowers subagent-driven development with disjoint ownership, TDD and independent gates. User explicitly approved the prior product proposal and autonomous implementation/publication/acceptance; do not repeat approval questions.

## Binding scope

The 2026-10-23 user request authorizes: first repair and publish 0.1.1; then finish and publish 0.2 rule search, new-goal creation and save/restore; then run a genuine bounded AI proof-completion experiment. No broad platform, model training, fake adoption or answer leakage. Preserve existing code/history and all failed evidence; no deletion. Mathematical semantics remain exclusively MoonBit. Existing replay/list retain their documented behavior, but model-visible observations MUST NOT include original proof arrays, source text, future or target-as-premise labels.

## Decisions and contracts

- Work stays in this standalone repository, branch codex/moonmetamath-v0.2. Root owns release integration and merges to main after gates. Native collaboration plus .superpowers ledger replaces shell-specific skill helper scripts; no automatic cleanup.
- 0.1.1 only fixes source-root/export IO classification and stale publication prose, with narrow regression tests, version/CI/registry/archive acceptance.
- 0.2 extends schema1 additively. New operations are rules, preview, create_goal. Core owner writes all native semantics and dispatch integration; frontend consumes the exact contract below.
- rules request: database_id, target_label, optional query/typecode/offset/limit (default20, max100). Result data: rules[{label,kind,conclusion,mandatory_hypotheses:[{label,kind,expression}],disjoint:[[String,String]]}],total,offset. Include only active hypotheses and visible axioms/earlier verified theorems; never original proof or future/target labels. Search label/conclusion text, typecode exact first token.
- preview request: session_id,label. Result data:event,view from a private copy using the same execute_op; no mutation of original stack/events/state/budget. Errors preserve original state.
- create_goal request: database_id,context_label,new_label,goal:String[], optional limits. Use the chosen existing $p's original prefix and active context. Preserve its hypotheses and $d; replace its target with a new incomplete $p and close scopes. Parse/verify this independent generated database, register a new handle, and return database_id,target_label,entry,sources,view-compatible metadata. No free-form axiom insertion. User edits only goal and label, UI explicitly explains inherited context. Reject namespace collisions, unknown/inactive tokens, malformed/empty goals. Prefix proof verification remains authoritative.
- Saved work schema1: entry, sources[{source_id,text,sha256}], target_label, actions:[{operation:apply_label,label}], completed. Hash is source identity, never a proof verdict. Strict validation, fixed size/step caps. Rebuild a fresh core, load/verify/start/replay actions, and finish only if saved completed. A failed restoration must not overwrite the active work. Canonical action list after rewind contains only remaining successful actions; no raw handle/internal-stack serialization. Browser file export/import plus size-limited local last-save recovery; shared host JS helper testable with an async request function.
- UI adds rule lookup/detail/preview, context-based new goal, save/import/restore and three short progressive exercises. No framework or server-side storage. Preserve existing replay separation/cancellation/export.
- AI is a local CLI adapter to existing configured OpenAI-compatible credentials, read in process only; never publish keys, raw auth configuration or credential-bearing URLs. Perform a bounded real preflight with effective model provenance. Fixed small tasks plus simple bounded search baseline. Policy receives allowlisted goals/hypotheses/rules/stack and feedback only; no list/replay/raw sources or original proof. All successful candidates go through independent official C verification. Per-task call/action/time budgets, failures/timeouts retained. No success-rate promise and no new-math claim.

## Tasks and gates

1. Patch release: reproduce root/export IO failures, add failing host tests, fix IO boundaries, update docs/version0.1.1, full existing checks, independent review, main CI, Mooncakes actual manifest and fresh registry consumer, portable archive/release download. Complete before mutating 0.2 core.
2. Native 0.2: implement/test rules visibility/filtering/pagination, preview atomicity and inherited-context new goals; no original proof in rules. Two backends, 79 existing fixtures and independent exported-goal verification. Review diff before integration.
3. Persistence: shared strict hash/schema/replay helpers and tests for wrong sources, bad actions, tampering, invalid completed state and recovery equality. No direct state trust.
4. Frontend: integrate native contract/helper; actual browser tests for rule search/preview, new goal completion/export, refresh/file/local recovery, failed import preservation and cancellation. Three exercises cover short implication/equality, essential hypotheses, and disjoint-variable diagnostics.
5. AI: separate policy observation boundary tested with distinctive original-proof sentinel; real bounded model calls, fixed public tasks and baseline, metrics plus independent candidate checks. Publish prompts and redacted actual results, never a replay represented as model output.
6. Release0.2: full local checks and consumers including new APIs, whole-branch independent review, exact-source matrix CI and Pages, registry/package/download acceptance, docs and project reuse updates. Publish experiment results with true limitations. Stop temporary services, no persistent monitor.

## Completion criteria

0.1.1 is truly published and consumable. 0.2 users can locate a rule without knowing its label, preview atomically, create an incomplete goal in a stated context, save and restore partial work by replay, finish/export and independently verify it. AI experiment has real request provenance, leak-free observations, fixed budgets, baseline and honest per-task outcomes. Published artifacts/CI/registry/website are independently checked, and organizer/prize outcomes remain separate.
